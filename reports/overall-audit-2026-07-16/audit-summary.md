# 雁巢机会雷达整体审核

结论：系统已经具备可运行的数据接入、机会展示和验证工作台，但目前仍是“内部验证版”，不适合直接作为采购、上架或投放的商业决策依据。当前主要风险不是淘宝/1688 是否连通，而是趋势发现、供给验证、Seed 假设和销售证据的口径混合。

## P0

1. 1688 供给验证记录被计入趋势分析，导致采集漏斗和渠道有效映射率失真。
2. Seed 趋势在机会详情中被展示为 Google Trends 证据，真实与模拟来源没有贯穿展示和状态流转。
3. 国家趋势图是前端固定数组，不应作为国家级热度证据。

## P1

1. 采集记录大部分缺少 `run_id`；页面读取还会触发外部采集及写入，影响可复现性。
2. 没有持续调度、队列、重试和新鲜度告警，当前主要依赖人工运行。
3. Amazon/真实销售数据尚未接入，毛利、竞争和评论痛点无法闭环。
4. 1688 的“供应商数”实际上是单页最多 20 条报价样本，应改名并补充总量或分页口径。
5. 采集、连接测试和 OAuth 重授权缺少用户级权限控制。

## P2

1. Git 仓库没有初始提交，无法形成版本、回滚和发布基线。
2. 数据库结构由应用启动时创建，缺少版本化迁移和回滚策略。
3. 页面存在 8–10px 小字号、宽表横向溢出，以及尚未验证的键盘焦点和弹层退出行为。

## 通过的工程检查

- 49 个自动化测试通过。
- TypeScript 类型检查通过。
- 代码规范检查通过。
- 生产依赖安全审计未发现已知漏洞。
- 未执行完整生产构建（本次为审核任务，未要求）。
